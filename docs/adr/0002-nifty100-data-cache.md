# ADR 0002: NIFTY 100 Data Cache Design (Phase 4)

**Status:** Accepted
**Date:** 2026-10-21

## Context

`LiveYFinanceProvider` (the real market-data implementation behind
`MarketDataProvider`) has never been exercised against live data: this
development sandbox's egress proxy blocks `query1.finance.yahoo.com`
outright (verified directly). Every later phase that needs real price
history — analysis, ML training, risk, backtesting — needs *some* way to
develop and test against real data without live network access at request
time, while never fabricating data to fill that gap.

## Decision

A file-based local cache, populated by a script the user runs on their own
machine (with real internet access), not by this environment:

- **Format: Parquet**, one file per symbol, under `backend/app/data/cache/`.
  Chosen over CSV for binary size, faster read/write, and preserved dtypes
  (CSV round-trips numeric columns through string parsing, which is both
  slower and a source of subtle precision bugs across repeated writes).
- **`scripts/fetch_nifty100.py`** — run locally, not in this sandbox or CI.
  Fetches adjusted OHLCV (`auto_adjust=True`, so splits/dividends are
  reflected) for every symbol in `nifty100.SYMBOLS` plus the NIFTY 50
  benchmark, validates each via `cache.validate_ohlcv()`, and writes the
  Parquet files plus `cache_manifest.json` (per-symbol row count, date
  range, fetch timestamp, validation warnings).
- **`LiveYFinanceProvider.get_history()` is cache-first**: it checks the
  Parquet cache before calling the network. If a symbol is cached, the
  network is never touched for it. If not, it falls through to a real
  `yfinance` call (which will fail in this sandbox, by design — that's the
  documented limitation, not a bug to work around here).
- **The bulk cache is gitignored** (`backend/app/data/cache/*.parquet`,
  `cache_manifest.json`) — it's large and fully regeneratable by re-running
  the fetch script; committing it would bloat the repo for no benefit.
- **A small *is* committed**: `fetch_nifty100.py --out-fixture` writes ~3
  symbols × 90 days of *real* data (CSV, human-diffable) to
  `backend/app/tests/fixtures/real_ohlcv_sample/`, specifically so the test
  suite can validate cache/validation logic against real market data in CI,
  not just the synthetic fixtures in `test_market_data_cache.py`. This
  fixture does not exist yet as of this ADR — see `docs/limitations.md`;
  it has to be generated by a human running the script once.

## Validation, not blind trust

`validate_ohlcv()` checks for: missing columns, non-positive OHLC values,
negative volume, `high < low`, gaps longer than a configurable threshold,
and single-day moves >40% (a heuristic for an unadjusted split slipping
through). It returns warnings rather than raising — the fetch script prints
them and still caches the symbol, on the principle that a human should see
and decide about data-quality issues rather than have them silently hidden
*or* silently block an entire batch fetch over one problematic symbol.

## Consequences

- Nothing in this sandbox can currently populate real cache data — every
  "real" NIFTY 100 number quoted anywhere in this repo must trace back to a
  cache the user fetched locally and either committed (the small fixture)
  or ran locally for their own development use.
- `DevSampleProvider` (synthetic data) and the real cache are deliberately
  kept in separate, never-conflated code paths — `DataSource.DEV_SAMPLE` vs
  `DataSource.LIVE` on every row, enforced by the existing model field.
